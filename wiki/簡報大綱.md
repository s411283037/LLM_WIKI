## 故事線與投影片

### 1. 餐廳客服面對什麼問題？

- 主問題：「信義店這週六晚上七點，我們有七位，可以線上預約嗎？還有位嗎？」
- 先拆成訂位資格、營業時間與即時空位。
- 案例來源：[餐廳訂位模擬資料](../examples/restaurant-booking.md)（自編教學示例）。

### 2. 第一步：先找到可能相關的店規

- 介紹「檢索」與兩階段問答流程。
- 證據：[[papers/Dense Passage Retrieval for Open-Domain Question Answering#開放領域問答的兩階段流程]]。

### 3. 關鍵詞相同，不等於意思相同

- 用「帶小孩」與「接受兒童入場」解釋語意匹配。
- 清楚標示為 Wiki 教學類比。
- 證據：[[papers/Dense Passage Retrieval for Open-Domain Question Answering#語意匹配與關鍵詞匹配的差異]]。

### 4. 語意檢索並非永遠勝出

- Natural Questions 的 Top-20 結果：Single DPR 78.4%，BM25 59.1%。
- SQuAD 的 Top-20 結果：Single DPR 63.2%，BM25 68.8%。
- Single DPR 表示只使用各自單一資料集訓練。
- 強調資料集與問題特性會影響結果。
- 證據：[[papers/Dense Passage Retrieval for Open-Domain Question Answering#DPR 與 BM25 的主要檢索結果]]。

### 5. 第二步：根據找到的資料生成回答

- 解釋 RAG 如何把問題、檢索文件與生成器接在一起。
- 區分模型參數中的知識與可替換的外部資料。
- 證據：[[papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#RAG 的基本架構]]、[[papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#參數式與非參數式記憶]]。

### 6. 找到資料後，仍可能說出證據沒有寫的內容

- 生成器不只是複製檢索文件，也會使用參數式記憶。
- 這既可能補足正確答案，也可能讓回答超出來源證據。
- 證據：[[papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#RAG 不只是複製檢索文字]]。

### 7. 更新資料，不等於模型會自動知道資料正確

- 替換外部索引可以改變系統能取得的知識。
- 仍須管理資料版本、品質與適用範圍。
- 證據：[[papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#替換外部索引可更新可取得的知識]]。

### 8. 正確資料放進去，模型仍可能「迷失在中間」

- 說明關鍵文件位置改變時，多個受測模型出現 U 型表現曲線。
- 標示投影片數值來自 GPT-3.5-Turbo（0613）、多文件問答、20 份文件；不得省略模型與任務條件。
- 強調這是特定模型、任務與設定下的研究觀察，不是所有模型的固定行為。
- 證據：[[papers/Lost in the Middle - How Language Models Use Long Contexts#關鍵資訊的位置會影響表現]]。

### 9. 更多資料不一定帶來更好的回答

- 區分檢索召回率與回答模型準確率。
- 說明重新排序與適當截短是待測方向，不是保證有效的公式。
- 證據：[[papers/Lost in the Middle - How Language Models Use Long Contexts#更多檢索文件不一定帶來相同比例的回答改善]]。

### 10. 三個問題定位錯誤發生在哪裡

- 上下文相關性：是否找對分店與所需規則？
- 忠實度：回答中的每個主張是否由資料支持？
- 回答相關性：是否完整回應顧客真正詢問的內容？
- 強調自動評估是代理，不能取代資料 ID 與原文核對。
- 證據：[[papers/Ragas - Automated Evaluation of Retrieval Augmented Generation#Ragas 將 RAG 評估拆成三個面向]]、[[papers/Ragas - Automated Evaluation of Retrieval Augmented Generation#限制與適用範圍]]。

### 11. 什麼時候需要重新查資料或修正回答？

- 用 SELF-RAG 的四類反思標記解釋檢索必要性、相關性、支持度與有用性。
- 清楚標示本專案只借用概念設計 Graph，沒有訓練或部署 SELF-RAG。
- 證據：[[papers/SELF-RAG - Learning to Retrieve, Generate, and Critique through Self-Reflection#四類 reflection tokens]]。

### 12. 本專案的 Loop／Graph 與回退

- 來源到 Wiki：擷取 → 提案 → 確認 → 寫入 → lint。
- Wiki 到簡報：查詢 → 證據覆蓋 → 逐頁稿 → 主張核對 → HTML → 瀏覽測試。
- 以找錯分店、虛構空位與失效引用示範不同回退節點。
- Graph 是本作業的製作流程，不等同於 SELF-RAG 模型架構。

### 五篇完成後仍需在案例階段驗證

- 最終模型是否真的出現中間位置效應。
- 自編店規的資料 ID、證據覆蓋及故障注入結果。
- HTML 逐頁內容、引用可用性與手機版面。
- 實際製作錯誤的統計與 workflow 反思。
