# 評估

> 狀態：已匯入 5／5 篇主要論文；已涵蓋檢索、忠實度、回答相關性、位置穩定性與自我反思限制。

## 白話說明

評估不能只問「最後答對了嗎？」還要檢查錯誤發生在哪一步。第一篇論文分別測量檢索是否找到含答案的段落，以及最終問答是否命中標準答案。[[../papers/Dense Passage Retrieval for Open-Domain Question Answering#檢索表現與最終問答結果]]

## 要分開評估的部分

- 檢索結果是否相關：可檢查前 k 個結果中是否至少有一段包含答案。
- 回答是否忠於找到的資料：RAG 原始論文顯示生成器可能使用檢索文件以外的參數知識；可用 Ragas 類型的主張支持檢查輔助評估，但仍須核對原始資料。
- 回答是否真正解決使用者問題：第一篇論文以 Exact Match 測量抽取答案是否與標準答案一致；生成式客服回答需要其他評估方式，仍待後續來源補充。
- 模型是否穩定使用已提供的資料：應改變正確文件的位置與上下文長度，觀察最佳和最差表現差距。[[../papers/Lost in the Middle - How Language Models Use Long Contexts#評估長上下文時應測試不同資訊位置]]

## 在餐廳訂位情境中的例子

- 檢索：詢問「可以帶小孩嗎？」時，前幾筆結果是否包含兒童入場規定？
- 最終回答：系統是否正確說出限制條件，而不是只找到文件卻回答錯誤？
- 位置穩定性：把正確分店規則放在輸入開頭、中間與結尾時，回答是否一致？此項測試須等正式案例資料建立後執行。

## 指標與定義

### Top-k retrieval accuracy（前 k 筆檢索準確率）

計算有多少比例的問題，能在前 k 個檢索段落中找到至少一個包含答案的段落。[[../papers/Dense Passage Retrieval for Open-Domain Question Answering#DPR 與 BM25 的主要檢索結果]]

這個指標不能單獨證明最終回答正確，也不直接衡量生成回答是否忠於來源。

### 任務分數與人工評估

RAG 原始論文在不同任務使用 Exact Match、BLEU、Rouge-L、分類準確率及人工評估。這些結果能比較論文中的模型表現，但不能直接視為所有餐廳客服回答的通用評估標準。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#論文中的生成效果]]

### 位置穩定性

Lost in the Middle 建議比較關鍵資訊位於不同位置時的最佳與最差表現。如果結果差異很大，就不能只因模型的 context window 足夠長而認定它能穩定使用所有內容。[[../papers/Lost in the Middle - How Language Models Use Long Contexts#評估長上下文時應測試不同資訊位置]]

### Faithfulness（忠實度）

Ragas 先把回答拆成可檢查主張，再計算有多少主張能由上下文支持。它檢查的是「回答是否符合提供的資料」，不是外部世界中的絕對正確性。[[../papers/Ragas - Automated Evaluation of Retrieval Augmented Generation#Faithfulness 的計算方式]]

### Answer relevance（回答相關性）

檢查回答是否直接回應問題，並避免不完整或多餘資訊。論文的這項指標不評估事實性，因此高分不能證明答案正確。[[../papers/Ragas - Automated Evaluation of Retrieval Augmented Generation#Answer relevance 不評估事實性]]

### Context relevance（上下文相關性）

檢查交給生成模型的上下文是否聚焦、是否含有太多無關內容。這不等同於完整的檢索召回率，也不能證明沒有漏掉必要資料。[[../papers/Ragas - Automated Evaluation of Retrieval Augmented Generation#Context relevance 衡量上下文是否聚焦]]

### 自我反思標記

SELF-RAG 使用 `Retrieve`、`ISREL`、`ISSUP`、`ISUSE` 判斷檢索必要性、資料相關性、支持程度與有用性。這些標記可啟發本專案的 Graph 節點，但模型判斷仍可能錯誤。[[../papers/SELF-RAG - Learning to Retrieve, Generate, and Critique through Self-Reflection#四類 reflection tokens]]

## 證據、限制與未定論

- 第一篇論文中，較高的檢索表現通常伴隨較高的最終問答表現，但 SQuAD 是例外。[[../papers/Dense Passage Retrieval for Open-Domain Question Answering#檢索表現與最終問答結果]]
- 因此目前只能說「檢索品質很重要」，不能說任一檢索指標提升必然改善所有 RAG 回答。
- Ragas 與 SELF-RAG 已提供忠實度、相關性、支持度及有用性的評估概念，但實務案例仍需定義門檻、人工抽查與規則式資料 ID 核對。
- RAG 在部分人工評估中比 BART 更具事實性，不代表所有回答都忠於檢索內容。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#論文中的生成效果]]
- 生成器能在檢索文件沒有答案時使用參數知識作答，因此「檢索正確」與「回答有證據支持」必須分開。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#RAG 不只是複製檢索文字]]
- 檢索召回率提高不一定等比例改善回答模型表現，應同時報告檢索與回答指標。[[../papers/Lost in the Middle - How Language Models Use Long Contexts#更多檢索文件不一定帶來相同比例的回答改善]]
- 位置效應不是所有模型與任務都同樣嚴重；案例測試結果必須如實記錄，不預設結論。[[../papers/Lost in the Middle - How Language Models Use Long Contexts#位置效應並非所有模型與任務都同樣嚴重]]
- Ragas 的 WikiEval 只有 50 個 Wikipedia 案例；0.95、0.78、0.70 是成對比較中與人工偏好一致的準確率，不是通用可靠度。[[../papers/Ragas - Automated Evaluation of Retrieval Augmented Generation#WikiEval 的驗證結果]]
- LLM 自動評分不能取代資料 ID、PDF 頁碼與人工抽查；高忠實度也可能只是忠於錯誤上下文。
- SELF-RAG 的人工檢查規模有限，且作者承認輸出仍可能未被引用完全支持。[[../papers/SELF-RAG - Learning to Retrieve, Generate, and Critique through Self-Reflection#自我反思仍可能判斷錯誤]]
