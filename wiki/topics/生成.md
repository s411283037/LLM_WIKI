# 生成

> 狀態：已匯入 5／5 篇主要論文；涵蓋生成架構、長上下文、忠實度與自我反思。

## 白話說明

生成是模型根據問題、先前輸出的文字及檢索到的外部內容，一個接一個產生答案文字。RAG 原始論文把預訓練的生成模型和外部文件檢索器結合，使模型不只依賴參數中記住的知識。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#RAG 的基本架構]]

## 在餐廳訂位情境中的角色

檢索器先找出正確分店的訂位規則、營業時間及可取得的空位資料；生成器再把這些內容整理成自然語言回答。正式店規尚未建立，目前僅為 Wiki 教學類比。

## 找到正確資料後如何形成回答

論文中的生成器同時接收原始問題與檢索文件。RAG-Sequence 假設整段輸出主要依據同一文件；RAG-Token 允許不同詞參考不同文件。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#RAG 的基本架構]]

這是該論文的模型形式，不是所有 RAG 系統都必須採用的設計。

## 為什麼找到對的資料仍可能答錯

- 生成器同時具有參數式記憶，不只是複製檢索文字。
- 論文顯示，即使檢索文件沒有正確答案，模型仍可能產生答案；這有時能補足資訊，也表示答案可能超出文件證據。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#RAG 不只是複製檢索文字]]
- 外部資料本身可能錯誤、過時或帶有偏見。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#限制與適用範圍]]
- 檢索器也可能反覆取回與輸入無關的相同文件，生成器隨後忽略檢索內容。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#限制與適用範圍]]
- 正確文件雖然已放入輸入，模型仍可能因文件位於長上下文中間而沒有穩定使用。[[../papers/Lost in the Middle - How Language Models Use Long Contexts#關鍵資訊的位置會影響表現]]
- 能接收更長的 context window，不代表能更有效使用其中每個位置。[[../papers/Lost in the Middle - How Language Models Use Long Contexts#長上下文容量不等於能有效使用長上下文]]

## 如何評估

RAG 原始論文使用任務分數及人工評估比較生成結果。在 Jeopardy 任務中，評估者較常認為 RAG 比 BART 更具事實性與具體性，但仍存在兩者都差或沒有多數意見的案例。[[../papers/Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks#論文中的生成效果]]

這不足以建立通用的 RAG 忠實度評估方式，後續等待 Ragas 等主要論文補充。參見 [[評估]]。

此外，長上下文評估應改變關鍵文件的位置與文件數量，不能只測一種固定排列。[[../papers/Lost in the Middle - How Language Models Use Long Contexts#評估長上下文時應測試不同資訊位置]]

Ragas 把答案拆成主張，再檢查每個主張是否能由上下文支持；這能檢測「店規正確，但回答自行補出空位」的情況。[[../papers/Ragas - Automated Evaluation of Retrieval Augmented Generation#Faithfulness 的計算方式]]

SELF-RAG 以 `ISSUP` 反思標記估計候選片段是否受文件支持，再和相關性及有用性一起選擇輸出。這是專門訓練模型的做法，不能當成一般生成模型天然具備的能力。[[../papers/SELF-RAG - Learning to Retrieve, Generate, and Critique through Self-Reflection#四類 reflection tokens]]

## 證據、限制與未定論

> [!warning] 未定論
> - 本論文支持 RAG 在特定任務上比 BART 更具事實性，但不能推廣成 RAG 能消除幻覺。
> - 「檢索文件正確」與「生成內容完全受文件支持」必須分開檢查。
> - Ragas 提供自動化忠實度代理，SELF-RAG 提供學習式支持度標記；兩者仍不能取代原始證據與人工抽查。
> - Ragas 已提供自動化忠實度代理，但評分器本身可能出錯，仍須保留資料 ID 與原文核對。
> - 位置效應依模型、任務、提示與長度而變；正式餐廳案例必須實測，不能預設一定出現。
> - SELF-RAG 的自我反思也非完美；論文承認輸出仍可能沒有被引用完全支持。
